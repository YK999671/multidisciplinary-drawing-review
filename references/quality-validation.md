# 质量验证与使用限制

## 每轮项目审查

1. 运行 validate_review.py，报告它实际验证的引用、版本及状态约束；--verify-source-files 读取真实源文件核对哈希，失败不得静默更新哈希，先核查并发修改和失效检查。
2. 对照图面执行 coverage-and-delivery.md 的反查。脚本不能验证图纸语义、规则适用性真实性、证据的实际独立性或范围是否完整。
3. 高影响确认项回看原图，待确认项核查是否错误降级；通过项抽查；保存样本及结果。
4. 检查本轮新增证据的原文/路径、对象可见性、变换、尺寸覆盖及图片范围，按[CAD证据核验](cad-evidence-verification.md)处理。核查报告链接与附件存在；历史继承证据的限制继续保留。
5. 发布前对照台账核报告、问题清单、检查清单和续审入口的轮次、数量与状态。未完成工作轮次不得覆盖最新已验证成果；结构校验通过也不能代替图面回看。

## Skill 自检

```text
python -X utf8 <skill-creator目录>/scripts/quick_validate.py <本skill目录>
python -X utf8 <本skill目录>/scripts/test_validate_review.py
python -X utf8 <本skill目录>/scripts/test_review_workflow.py
python -X utf8 <本skill目录>/scripts/test_parallel_review.py
```

脚本测试验证应拒绝的台账：过期证据、重复证据冒充独立证据、无依据不适用、未复核关闭、计划范围无人执行、源文件变化；也验证高影响低证据疑点可保留而不伪装确认。

## 实际能力验证

在真实项目或有已知答案的脱敏图纸上记录预期问题、实际发现、漏报、误报、证据位置及覆盖遗漏。样例至少逐步覆盖多图框 DWG、外参/嵌套块、特殊层、跨层系统、室内外接驳、局部变更与精装接入。

人工复核预期答案，避免把另一份模型生成清单当事实。记录通过项的抽查和资料缺失时的判断。只针对已观察问题修正规则；结构校验与合成台账测试不等于真实图纸验证。初版专业规则为待项目验证，不能给出未经实测的准确率。

已有项目的局部证据可用于回归检查：互斥备选值、同源重复视图、编号数量与总数不一致、同组管路上下端编号、默认标高的局部例外、尺寸文字覆盖及父子检查状态。测试应验证实际判定行为，不能只检查规则文字存在。局部案例通过不代表全专业能力已验证，也不能把尚未完成复核的工作记录转成正确答案。
