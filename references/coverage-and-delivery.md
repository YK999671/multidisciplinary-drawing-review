# 覆盖、完成度与交付

从任务范围、目录、说明和项目条件确定预期单体、实际楼层、专业、系统和专项。区分 received、expected_missing、applicability_unknown、not_applicable。缺失须依据，未知适用性和读取失败不能从分母消失。

每条检查是 scope × rule × target_depth，有唯一 check_id 和所需输入。每个适用范围有检查，每条适用规则有实例或不适用理由。脚本只验证已声明计划，遗漏规则和范围靠目录/图面反查。

## 深度

- L0 未检查。
- L1 文件、图面、版本、说明与适用范围。
- L2 索引、跨图编号、空间/系统关系和参数对应。
- L3 对象、系统分支、定位、尺寸、标高、容量表达与接口实质核对。
- L4 构造、安装/更换路径、工序和明确输入下的专项复核。

L4 不自动表示专业验算。默认全部适用范围完成 L1/L2；主要系统、关键对象和接口安排 L3，构造/检修安排 L4。每项写明目标，报告列出未做到对象深审的部分，不只写“全量”。

解析、适用、结果、复核状态分列；needs_confirmation/blocked 不是通过。重复母版深审后，每实例核对方向、轴网、结构、洞口、竖井、设备、标高和版本；差异触发独立检查，不可直接批量打勾。

## 统计

分别报告文件、图面、专业、实际楼层/空间、系统分支、接口、规则执行和深度；给分子/分母、分母依据及未知数，不汇成设计质量分。

脚本 planned_check_completion：达到目标深度且 reviewed，结果 pass 或 issue 的检查数 / applicability!=no 的计划检查数。发现问题可以表示检查完成，不表示问题解决。分母零时比例 null，不报 100%；未知适用性仍在分母。

该指标称“声明检查记录完成率”，不称整套工作量进度、工时完成率或合格率。项目清单由实际范围生成，不把某次项目的条目数量固化为通用标准。

综合任务与执行检查使用可选 tasks 层级关联，具体契约和推导见[工作状态与发布工具](workflow-tools.md)。历史综合检查先保留并说明范围重叠，不自动迁移。新增细项应有独立对象、规则与完成目标，不为提高比例拆项；拆解替代原项时保存映射和原目标。脚本检查计数不是去重后的工作量统计，报告须披露分母增减及原因。

子项完成不自动完成父项。例如编号、数量和一般厚度已核，逐桩定位与墙柱插筋未核时，综合基础项仍未完成。用户询问总体百分比时，给该计数及局限，同时说明全层、系统及关键接口的实质完成情况；没有可辩护的工作量估算就不另造总体百分比。

## 报告前反查

1. 从发图清单查漏图、图框查漏识别图面、系统图查漏支路、范围表查漏专业/特殊层。
2. 规则反查执行记录，记录反查证据有效版，证据反查原图。
3. 高影响确认项全部回查；高影响待确认单列。通过项也抽查，说明样本。
4. 缺口写位置、受阻检查、缺少资料及补充后的重查范围。

## 交付与复审

独立输出 review-output/项目/轮次：源清单、图面有效版、规则基线、关系、计划/结果、问题台账、review.json、校验结果、report.md、evidence/。不为无内容附件造空文件。

报告先范围/覆盖，再确认问题、高影响待确认、其他风险、限制、优先答疑及复审状态。问题包含位置、证据双方、影响、需设计答复事项和时间窗口。

复审按图号/版次与对象变化，沿对象→系统→接口→关联专业传播。改名不自动成为新设计，相同图号不代表内容未变。新轮记录沿用依据及失效检查，保留旧轮并复核未直接修改的上下游。

## 长任务与中断续审

在项目输出目录维护简短续审入口，包含最新已验证报告/台账、当前工作轮次、用户确认与资料缺口、已完成检查ID、候选发现、下一步对象及未结束进程。脚本有重跑覆盖或先后依赖时记录，避免覆盖人工回看映射。

使用 review_workflow.py 时，workflow.json 为正式入口，指向不可覆盖的状态快照及 resume.md；每批工作后实际调用 checkpoint。人工摘要可保留，但不能与机器入口互相覆盖或承担第二个正式状态源。

“最新已验证成果”与“正在整理的工作轮次”分别指向。仅生成截图或追踪JSON、尚未汇总回查的结果标为工作记录，不更新为正式完成数。中断后检查已有产物和运行状态，从断点继续；不因日期变更重新盘点所有几何，也不把旧缓存当成新核查。

资料缺失只阻塞关联检查。问题集中说明所缺资料、受影响对象及补充后动作；已明确暂未提供或已确认的版本不反复询问。用户询问skill或视频等事项时保存审图断点，不擅自把旁支任务纳入工程审核范围。
